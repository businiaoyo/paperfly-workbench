## 持续扩展方向（用户确认，2026-11-07）

后续将加入创建/保存工作台组合、侧栏样式、背景、比例、桌面快捷方式，以及一张卡片包含多个应用的组合能力。架构需要覆盖这些方向，功能按阶段实现。

0.9.2 架构候选已落实不可变配置模型、稳定工作台/卡片 ID、当前草稿与保存组合隔离、版本化存储、旧列表迁移、异步原子写入和独立布局计算。默认界面行为保持原样；多应用卡片目前只有数据模型支持。详见 [架构设计](architecture.md) 和根目录 [开发约定](../AGENTS.md)。

建议实施顺序：

1. 组合创建、命名、保存、恢复与显式覆盖；明确自动保存当前状态与手动保存组合的区别。
2. 侧栏样式、背景、窗口比例及其横竖屏适配，统一由样式配置和布局策略驱动。
3. 基于稳定工作台 ID 的桌面快捷方式，处理组合删除、未激活和缺失应用。
4. 多应用卡片的会话协调、组内布局与焦点，再实现组合编辑/预览；成员失败可独立恢复。

常用应用兼容、长时间性能与暂离恢复仍按前述清单推进。跨应用拖拽、系统级进入手势另行评估。

## 验证原则

保持 0.5 的真实应用输入、实时侧窗、最后选择生效及异常退出恢复。数量扩展需验证至少 6 个真实应用、多次添加移除、滚动后切换、顺序恢复和内存读数；内存不可读取时不能显示为零或虚构估计。

新增兼容待办：荣耀电子邮件首次使用页在画面恢复后不出帧，需独立排查；当前没有操作其账号或授权。

0.9.2 发布前待办：开发期实测旋转后时钟及部分静态侧窗黑屏，0.9.1 对照未复现相同问题，尚不能排除回归。先排查配置异步加载与渲染更新时序，再验收重构版；平板当前恢复使用 0.9.1。详见 [架构验证](architecture-validation.md)。


## 0.10.0 功能扩展

已实现组合的创建、保存、打开、重命名、覆盖与删除；左右/宽度/紧凑侧栏、颜色/渐变/自选图片背景、主窗缩放与宽高比；保存组合的系统桌面快捷方式；多应用卡片的合并/拆分、共同主次切换、独立输入焦点、方向和首成员比例。配置 schema 3 迁移保留稳定 ID 和保存组合隔离，调度由独立 CardSession 管理。

返回修复覆盖承载窗口无焦点 ANR、按键分发完成后恢复当前焦点、根页任务退出后的空显示器恢复。渲染继续复用有效 Surface，实际场景尺寸变化后重算成员画布，修正旋转前后比例不一致。

后续继续：更多应用/输入法兼容、短窄窗口和复杂组内布局、图片引用的资源清理、缺失成员的管理入口、长时性能/功耗和更多设备。详见 [0.10 功能验证](feature-expansion-validation.md)。

现有配置结构无需迁移，schema 3 不变。见 [应用组合启动验证](application-set-validation.md)。
