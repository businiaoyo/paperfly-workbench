# 0.9.1 侧栏末尾添加卡片

日期：2026-11-07。versionName 0.9.1 / versionCode 15，调试签名。

侧窗列表的最后一项增加带虚线边框的“＋ 添加应用”卡片，点击打开现有图标搜索及管理面板。卡片参与侧栏的滚动范围与边界计算，普通、整个工作台全屏及横竖屏均可使用。面板支持连续添加，关闭后保留当前模式和主窗。一个应用或没有应用时也保留入口。

卡片使用现有侧栏的手势方向判定：轻点打开面板，上下拖动滚动列表；横滑和取消不触发添加或移除。它不加入真实应用槽位、显示器、内存统计或持久应用列表。

在荣耀 WIN 平板 HES-W00（Android 17 / API 37、MagicOS 11.0.0）实测。安装时工作台已有用户的 9 个应用，逐次滚动到末尾后确认卡片完整可见；通过卡片临时加入系统设置，使真实应用数增加到 10。竖屏全屏及普通模式都能从卡片打开选择面板。卡片自身的纵向拖动用于滚动，没有误触打开。测试后只移出临时系统设置，保留用户应用和顺序，并恢复原显示模式和自动旋转设置。

`assembleDebug`、`testDebugUnitTest`、`lintDebug` 通过，50 项现有单元测试无失败，Lint 无错误。新增视图和手势接入通过实机检查，没有增加仅复述界面实现的单元测试。构建仍为单 APK，无新增运行时依赖或权限。

原始截图及状态在本机 `.runtime/v09-validation/`，交付证据位于 `dist/rail-add-validation/`，包含横竖屏卡片截图、面板截图、验证结果、源文件和安装包校验。验证范围限于本机与本轮交互，不代表全部设备和应用兼容。

0.9.1 同时处理了实测中旋转或关闭工作台弹窗后部分窗口画面未恢复的问题：重建本 App 的渲染目标，并通过 [VirtualDisplay.setSurface](https://developer.android.com/reference/android/hardware/display/VirtualDisplay#setSurface(android.view.Surface)) 重新绑定到原有显示器。后台校验应用 UID、会话和已承载组件，旧 Surface 在替换后释放；保留应用任务和显示器，不重新启动应用。复测包括连续横竖屏切换及添加面板关闭后的计算器与浏览器画面。

已知限制：电子邮件首次使用页在重新绑定后仍可能停留于等待画面的状态，未列为兼容性通过项；未操作其账号或首次使用授权。计算器和浏览器的恢复已通过实际画面核对。
