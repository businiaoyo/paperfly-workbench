# 关闭成员的闪烁与补位修正

> 历史记录。2026-11-13 再次逐帧复验发现，test.8 仍有系统显示器截图过渡、新帧与裁剪不同步，以及密度变化导致的应用重建。下文把剩余叠化仅归因于第三方内容重排并不充分；当前修正与最终验收见 [test.9 帧同步与关闭复验](split-close-frame-sync-validation.md)。

2026-11-13，0.17.0-test.8 / versionCode 46 / schema 8。仅平板测试包，不发布 NAS。

## 问题与修正

test.7 的关闭回归只验证最终归属、显示器和 Surface，没有覆盖中间绘制帧。本轮在 Y700 的双应用分屏中关闭 LocalSend，录屏确认剩余哔哩哔哩先被深色“正在调整窗口”遮住，然后突然放大。`remove` 启动的动画被后续 `relayout`、`resizeCanvas` 和完成回调的立即定位打断；单独以宽度推导显示高度，也无法在画布比例变化时保持显示矩形连续。

- 关闭补位进入 `liveReflow`，布局复算及异步 resize 完成只更新运动目标，保留当前位置、宽高及速度。动画与画布提交完成后退出该状态；连续关闭可继续重定向。
- 保留已有实时画面，关闭导致剩余成员画布变化时也不再盖加载层；只 resize 实际改变的画布，不重建剩余成员 TextureView、Surface、任务或显示器。
- 显示宽高独立运动。`StageLayout.CardPose` 同步使用纵向缩放计算透视中心与位移，保证显示顶部、底部不因逻辑画布比例改变而偏移。几何计算留在 StageLayout，View 变换留在 StageCardPose。
- 沿用后台任务交还、显示器归属检查和按需关闭菜单。不添加内容遮挡控件，不修改 schema，不改保存组合。

录屏复核曾发现一个仅检查运动数值无法发现的画面上移问题。最终增加实际 View 矩阵边界断言及纯几何测试，按可见画面复验；没有采用重建 TextureView 或截图占位来掩盖问题。

## 自动及实机验证

架构检查、220 项单元测试、Debug/Release 构建、Lint 通过，Lint 0 错误、47 警告。新增几何测试覆盖不同横纵缩放下的顶部/底部锚定与共享透视中心。

私有 Debug 回归 `WindowCloseValidation` 在 `OnPreDraw` 采集关闭过程的实际绘制边界、加载层和资源身份，检查多个中间位置、最大单帧位移及矩阵边界；覆盖中间成员、当前成员、最后成员接续侧栏，以及整个工作台全屏下间隔 80 ms 连续关闭两成员。正常/两种全屏、分隔条轻点/拖动、主次交换、侧栏加号和原草稿恢复继续验证。逐帧数据先留内存，结束后写本轮结果；Release 不启用验证入口。

最终横竖屏各 **112 项断言通过**。关闭补位每个移动成员采到 45–65 个中间绘制帧；最大单帧位移占该次总位移约 5.7%–26.7%，没有一步跳到终点；加载层未出现，保留成员的显示器/Surface 身份未变。横竖屏测试后配置 JSON 与本轮初始快照语义完全相同，自动旋转和 user_rotation 均恢复并核对。

设备为本轮授权的联想 Y700 `HA2HEFTM`，Android 16。安装前通过左上角返回首页，确认所属显示器已释放；安装后从 App 内“已配对，直接激活”恢复。荣耀未接入，vivo 未操作。

现场来自本轮新快照：哔哩哔哩主卡片，番茄免费小说、LocalSend 为两个侧卡片，普通横屏，自动旋转 1、user_rotation 1。测试临时把现有成员组合，并使用本轮最近列表中的浏览器作为侧卡片；通过 App 草稿恢复原有应用、卡片 ID、顺序、焦点、样式与偏好，移除临时浏览器。没有用历史五应用快照覆盖用户后来移除的浏览器/微信，没有操作第三方账号或首次使用协议。

## 证据与范围

本轮材料位于 `.runtime/split-close-smooth-20261113/`：`before.mp4` 为 test.7 复现；`verified.mp4` 与 `verified-transition.png` 为最终代码同一路径的录屏/逐帧拼图。`after.mp4`、`final.mp4` 等是开发中间版本，不作为最终验收。最终横竖屏结果与录屏单独保存在该目录。

本修正消除工作台主动叠加的加载闪屏、补位跳变和矩阵定位偏移。第三方应用收到实际宽高变化后仍可执行自身重排/过渡；哔哩哔哩录屏中可见内容重排的短暂叠化，这不等于所有应用或设备均能做到内部内容零变化。工作台没有更改全局动画设置或扩大 shell 权限。
