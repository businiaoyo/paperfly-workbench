# 0.5.0 重做与实机验证

日期：2026-11-07。构建：versionName 0.5.0 / versionCode 10，调试签名。这是限定设备和应用样本的验证记录，不代表全部 Android 应用的兼容性认证。

## 对象与证据

实现目标机为用户授权的荣耀 WIN 平板 HES-W00，Android 17 / API 37，MagicOS 11.0.0，固件 `HES-W00 11.0.0.112(C00E100R101P1)`。横屏 2304×1440、密度 360。测试应用为系统计算器、时钟、设置。每个应用在自己的 1920×1200、密度 300 的虚拟显示器上运行，画面直接进入工作台 TextureView。

连接的 vivo iPA2693 用作前一阶段的原生行为参考，研究见 [原生工作台研究](native-stage-study.md)；本轮没有给 vivo 安装重做版。

原始 QA 证据保存在本地 `.runtime/live-validation/`。界面截图、任务/显示器转储、状态检查、短录屏相互核对。部分系统界面无法由 UIAutomator 获取树，脚本在失败时丢弃旧 XML，以截图和窗口记录为准。含设置账户、Wi-Fi 及无关任务的原始记录不复制到交付目录。

## 实测结果

| 检查 | 结果及限制 |
| --- | --- |
| 真实触控 | 通过渲染窗口内的按钮完成 `7 + 2 = 9`，未直接修改计算器数据 |
| 实时侧窗 | 启动秒表后交换到计算器，侧位秒表继续变化；最终录屏包含连续交换 |
| 动画连续性 | 逐帧查看交换中间画面，两个真实窗口同时移动、缩放。改为统一 Choreographer 与可重定向的阻尼运动后，没有首个 ValueAnimator 试验版的直接跳变 |
| 30 次普通交换 | 每次等待落位后检查槽位，全部符合交换规则 |
| 10 组连续点选 | 每组先点侧位 1，随即点未移动的侧位 2；最后一个目标全部生效，保留显示器身份。主机命令结束间隔约 29–40 ms，仅表示测试发令间隔，不是触摸延迟或动画耗时 |
| 任务连续性 | 压测前后任务 667 / 673 / 679 与 1920×1200 边界保持，三个应用均可见；交换时未重新启动任务 |
| 应用内输入法 | 设置搜索框通过实际显示的键盘输入 `123`；交换到时钟再返回后继续输入 `1`，得到 `1231`。返回按钮先收起键盘，再退出搜索页 |
| 添加应用的搜索框 | 修正弹窗焦点后，键盘显示在工作台设备屏幕上；实际点键输入 `12`。搜索及取消工作正常 |
| 添加 / 移除 | 工作台内加入设置成为第三个窗口；通过窗口菜单移出设置，剩余计算器和时钟继续运行，设置返回物理显示器任务 |
| 应用内弹窗 | 计算器自己的模式菜单显示在其窗口内，返回按钮可关闭，不成为新的侧卡 |
| 正常退出 | 返回入口，所有测试任务返回显示器 0，工作台虚拟显示器全部释放 |
| Home | 同上；再次进入不重新 USB 激活，helper PID 不变 |
| 强制停止 App | 虚拟显示器释放，三个测试任务仍在；重新打开 App 和工作台不重新 USB 激活，helper PID 不变 |
| helper 被直接 SIGKILL | 核验 PID 与进程名称后执行。显示器自动释放、任务回到显示器 0；界面回入口并提示未激活。随后已重新激活 |
| 转屏 | 横屏会话转竖屏再恢复横屏，真实画面保留，主窗/侧窗按新屏幕重排。当前会话保持原来的应用逻辑宽高比，竖屏留白较多；未据此声明完整的竖屏优化 |
| 系统设置 | 切换路径不改动画倍率；测试后核对 window / transition 为 1.0，animator 为原先未设置的 null。临时转屏测试后恢复自动旋转及原 user_rotation |

回桌面、强停、helper 死亡的检查还确认测试包的任务仍在系统中，不只检查“虚拟显示器数量为零”。最后一个补丁只修正工作台自身弹窗的焦点，之后重新构建、安装并复测弹窗键盘、移除、应用内菜单与真实动画。

## 修正过的失败

1. 旧版依赖厂商 freeform、快照和全局动画开关的交换路径被替换。保留旧恢复代码只用于处理历史记录。
2. shell 的 `WindowManagerGlobal` 初始化在此固件失败，改由 system service Binder 取得窗口服务；任务信息采用反射读取，不再错误强转为 `RunningTaskInfo`。
3. 初版动画在实机录屏中直接跳变，改为同一个 Choreographer 帧时钟驱动所有变换。
4. 主窗点击会抢走虚拟应用的输入焦点，导致键盘首字符后收起。承载窗口改为不争夺焦点；应用、工作台对话框分别显式获得正确显示器的焦点。
5. 双设备激活脚本明确选择目标序列号，唯一安装 App 的设备才自动选择；阻止 ADB 读取循环的标准输入而漏掉下一台设备。

## 自动检查与交付

`assembleDebug`、`testDebugUnitTest`、`lintDebug` 通过。32 项单元测试中，7 项针对新的槽位和运动状态（其他 25 项属于保留模块）；没有失败或跳过。Lint 0 错误、9 警告：旧 target API、导出 Provider、数据提取规则、触摸无障碍和界面文本。导出 Provider 有 shell/root 身份、版本和 UID 检查；警告仍保留在报告中，不视为已完整解决无障碍适配。

交付文件位于 `dist/`：新版 APK、SHA-256、激活脚本、使用说明、仅含计算器和时钟的实机录屏与截图。`dist/rebuild-validation/source-sha256.txt` 标识构建源文件；`package-check.json` 核对交付 APK 与设备安装包。

## 尚未证明的范围

- USB 物理拔线后的操作未在本轮实测。运行链路和后台进程位于设备内，没有电脑画面转发或持续控制依赖。
- 其他手机、平板、系统版本，以及其他输入法、键鼠、触控笔、多点手势尚未逐项验证。
- 受保护画面或限制副屏的应用可能不能加入或不能显示；不绕过其限制。
- 没有做长时间电量、温度、内存压力或精确触摸延迟/掉帧测试。录屏帧率元数据和主机发令间隔不等于真实触摸到显示的性能指标。
- 本版没有应用分组、跨应用拖拽、系统级进入手势和 vivo 的透视侧卡效果。
