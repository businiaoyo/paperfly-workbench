## 数据与模块

- `WindowPlacement` 是纯 Java 归一化矩形与层级；`WindowArrangements` 计算半屏/网格；`WorkspaceCard` 保留分屏与自由布局。`CardSession` 管理归属、合并、移出与焦点。没有把应用组合变成分屏卡片。
- `AppTarget.id` 是窗口身份，`component` 是启动目标；旧实例 ID 沿用规范化组件，额外实例使用 UUID。同包额外实例不能共享窗口 ID。临时 display/task/Surface 不进入配置。
- schema 1–4 补自由布局默认值；schema 5 补稳定窗口身份与层级；schema 6 写对象形式的应用成员和 `focusedWindowId`。损坏、未来版本与保存失败保护沿用 Repository。已保存组合与运行草稿保持隔离。
- `WindowChrome`、`WindowArrangementPanel`、`StageDock`、`WindowOverview` 负责呈现；`StageKeyboard` 跟踪宿主转发的按键；`StagePresentation` 管理暂态展示。Activity 仍编排事件与生命周期，下一步双屏前应先抽出场景和窗口生命周期。
- 新 Binder 方法只接受自有窗口 ID / 自有显示器与受限输入；现有 UID、session、用户和宿主校验保留。未增加任意主机连接、通用 shell 输入或远程更新权限。
- 全屏、总览、最小化、Dock/侧栏显示不改变应用画布。显式尺寸、方向、组布局变化才调整受影响成员。Dock 占位属于绘制规则，普通画布几何不受它影响。
- 暂离会话保留在内存；进程重启恢复配置，并不承诺所有第三方应用内部页面/媒体状态完全恢复。

## 验证

- `python3 scripts/check-architecture.py` 通过。
- `:app:testDebugUnitTest`：196 项通过，0 失败。包含 schema 4/5 迁移、schema 6 往返、稳定身份、多实例焦点/移除、保存组合隔离、损坏/未来版本保护、保存失败重试、布局边界与输入策略。
- `:app:assembleDebug`、`:app:assembleRelease`、`:app:lintDebug` 通过。Lint 0 错误、45 警告（基线 37）；新增主要为自建 View、触控无障碍及明确左右方向提示，尚未作为无障碍验收通过。
- Debug 私有文件触发的 `ParityValidation`：21 项实机断言；记录同应用两个独立显示器，分组、全屏/退出、总览、最小化/还原、侧栏隐藏和弹窗关闭前后的显示器、画布及 Surface 对象身份，并验证拆出后原卡片 ID 保留。Release 只有空实现，无公开测试入口。
- `validation/probe` 提供无账号、无权限的临时应用：每实例显示 task/实例号、心跳、点击计数、输入框及原生拖放源/目标。不是产品依赖。
- 触控实测：浏览器移动/缩放；验证窗口左侧点击 2 次、右侧仍为 0；右侧输入框收到字符（使用现有输入法，未修改输入法设置）；Dock 浏览器拖入当前组、标题拖回侧栏。横竖屏都观察到持续真实画面。旋转可能由系统重建应用 Activity，不把任务保留误称为 Activity 不重建。
- 全屏断言是本设备与所测应用结论，不覆盖所有应用/设备。多窗口性能、全局键盘与双屏仍有明确欠项。

## 后续完成条件

1. 将显示场景、窗口生命周期与会话操作从 Activity 继续分离，再实现两个真实输出屏的独立工作区与断连恢复；需要外接显示器实际验证。

4. 补齐 Dock 固定项、超多窗口总览、不可用应用恢复、长时压力与后台恢复矩阵后，再讨论稳定发布。
