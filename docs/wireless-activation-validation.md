# 0.12.0 内置无线激活与荣耀验证

2026-11-08。荣耀 WIN 平板 HES-W00，Android 17 / MagicOS 11，设备 AKDPBB6A08000069。vivo 未安装或修改。

## 已实现

首页新增“无线激活 · 无需电脑”。App 内置本机端口发现、配对码认证、TLS 连接和辅助进程启动；用户只需操作系统无线调试页面及本 App。通知回复支持保持系统配对弹窗打开时输入六位代码；通知不可用时可分屏手动输入，端口发现不可用时可手填端口。已配对后可直接重新激活。

固定版本 LibADB Android BC（提交 b6c301dab4b83ae5892a7e68fdb96b6554e046a8）与 Bouncy Castle 1.84 编入同一个 APK，不依赖 Shizuku、终端或其他手机 App。上游源码、修改说明与许可在 third_party/libadb-android-bc；用户可在无线激活页查看开源许可。

实际套接字固定使用 127.0.0.1；NSD 仅接受本机地址。端口和代码格式有界校验，不提供主机地址或任意 shell 命令输入。身份由应用专用 RSA 密钥与自签证书组成，在 noBackupFilesDir 原子保存，配对码不持久化。配对与网络操作异步执行，可取消且有超时。

辅助进程通过 APK 内固定启动脚本启动，使用 shell-v2/raw 避免终端退出时清理后台进程；启动后尝试 setsid 脱离引导 shell 的会话，UID 和权限不变。客户端等类型化 Binder 建立后主动关闭 ADB，再确认 Binder 仍存活才宣告激活成功。临时前台服务与发现随之停止。

## 测试方式与边界

电脑用于安装和观察，不执行 USB 激活脚本。验证前强制关闭旧 App 进程、核对并结束本项目旧辅助进程，确认首页未激活；随后用 App 的“已配对，直接激活”启动新辅助进程，避免旧的同版本服务误判为成功。

首次配对已通过系统通知回复在荣耀上实测，系统已配对设备列表出现 OpenWorkbench。后续安装和进程重启保留同一私有密钥，使用本机发现的连接端口重新激活。服务日志确认辅助进程为 shell UID 2000，激活记录为 wireless，且 adb_connection_closed=true。

仅关闭无线调试后，辅助进程 PID 保持不变，工作台可重新打开原来的 9 个应用。物理拔线的完整结果另从平板内的一次性调试验证记录回收。

首轮等待物理拔线的自动记录超过 30 分钟后退出，结果仅说明超时当时 Binder 仍存活，不计作拔线操作验证通过。已将此一次性调试等待窗口延长为 8 小时，安装最终 APK，并再次通过 App 内无线激活启动新辅助进程，重新等待物理拔线。当前拔线输入、返回和切换记录仍待回收。

调试验证由私有文件一次性启用，没有导出的测试入口或新增 shell RPC；release 构建对应实现为空操作。测试记录本机 USB 物理连接状态、无线调试状态、辅助进程 PID、返回与交换后的 Binder/显示器状态，并保存原应用实时画面。测试不创建新组合，不操作账号，不清除第三方应用数据。

物理拔线与关闭 USB 调试开关分别记录。本轮用于实际拔线的场景保留 USB 调试开关开启；更严格的“双开关同时关闭”早期实验曾使服务被系统结束，不能据此承诺最终版在两开关都关闭或开发者选项关闭后仍永久运行。设备重启、APK 更新和系统回收辅助进程后仍需在 App 内重新激活。
