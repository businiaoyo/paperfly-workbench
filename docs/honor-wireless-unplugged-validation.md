# 0.15.2 荣耀无线激活：物理拔线复验

2026-11-13，Asia/Shanghai。设备 `AKDPBB6A08000069`，荣耀 WIN 平板 HES-W00。最终版本 0.15.2 / code 37；配置 schema 4。接续 [0.15.1 验证](honor-pairing-identity-validation.md)，本轮由用户再次反馈“仍不行”触发。

## 失败现场

用户确认执行了拔掉 USB、关闭再开启无线调试、输入配对码后自动激活。0.15.1 的现场是配对成功、阶段 connect、错误“未发现连接端口”，连接尝试数为 0，而不是连接拒绝或配对码错误。

先安装仅增加诊断的本地构建，未对 NAS 发布。用户物理拔线复现仍失败，私有轨迹显示：

- elapsedRealtime 2096363：认证配对完成，开始选择连接端口，候选为空。
- 2116363：20 秒等待结束，候选仍为空；发现监听持续由前台配对服务持有，未中途停止。
- 2135213：约 39 秒后才发现本机连接服务；NSD 的本机注册记录对应 00:42:39。

失败后接回 USB 时，电脑能识别 HES-W00 的 USB 硬件，但起初没有 ADB 接口；切换文件传输、重新开启 USB 调试后才恢复读取。检查发现“仅充电模式下允许 ADB 调试”关闭，后来通过系统界面开启为 `allow_charging_adb=1`。这与拔线后调试服务关闭的厂商行为相符；失败构建未记录当时 `adb_enabled` 的即时值，因此不把推断表述为系统内部因果已完整证明。

另外，实际发现记录出现同一本机服务的 `GUID (2)` 名称。Android NSD 会因名称冲突自动改名，而认证配对返回原 GUID；0.15.1 的严格字符串相等会排除该有效端口。[Android 官方 NSD 文档](https://developer.android.com/develop/connectivity/wifi/use-nsd) 明确说明这种自动重命名。荣耀关于调试自动关闭与充电模式开关的官方答答团回复见 [荣耀支持回复](https://club.honor.com/cn/thread-30234449-1-1.html)；该回复对应其他荣耀机型，本项目兼容结论仍限于本轮 HES-W00 实测。

## 改动

- `AdbEndpointCatalog.Endpoint.matches` 接受完整认证 GUID 后的有界数字冲突后缀，例如 ` (2)`；不同设备、任意前缀、非数字后缀、尾随文本或重复后缀不匹配。本机地址/型号过滤、回环套接字和 ADB 认证不变。
- `AdbPrerequisites` 提供纯 Java 厂商指引规则，`AdbDebugState` 是只读设置适配器。未知或不可读取的键为 -1，不把未知说成关闭，也不要求所有 Android 厂商都必须开启 USB 调试。
- 激活页补充荣耀/华为的“仅充电模式下允许 ADB 调试”与 USB 调试指引；连接端口未发现时根据可读的开关状态提示恢复步骤，保留已配对信息。App 不自行修改系统设置；本轮设备上的开关通过系统 UI 设置。
- `ActivationDiagnostics` 保存最多 80 条有界私有事件，包含发现生命周期、候选端口、身份摘要和调试开关状态。失败时另存冻结轨迹，避免等待 USB 重连期间被后续发现覆盖；每次操作重置过期连接诊断并记录开始/失败时间。原始 GUID 不写入新增轨迹，配对码、密钥、密码不进入日志。
- 不增加权限、任意主机或通用 shell 输入，不改窗口服务、配置数据格式或签名。配置 schema 仍为 4。

## 真实拔线验证

最终安装包已安装后，用户按要求在未接 USB 时完成配对和激活，并明确回复“未接 USB 时已成功，现已接回”。电脑端记录与 App 记录交叉核对如下，均为 2026-11-13 北京时间：

| 时间 | 证据 |
| --- | --- |
| 00:53:23.465 | 电脑检测到荣耀 USB 调试连接断开。 |
| 00:53:34.857 | App 本次配对/激活开始。 |
| 00:53:35.920 | App 核验 Binder 存活并关闭临时 ADB 连接后记录激活成功。 |
| 00:53:45.772 | 电脑才重新检测到 USB 连接。 |

激活确实发生在物理拔线期间，约 1.063 秒完成；没有用 USB 激活命令代替。用户报告执行了无线调试开关切换；机器记录独立证实的是 USB 断开区间、配对成功、连接和服务启动。

该次只有 `adb-AKDPBB6A08000069-0XR5OU (2):43249` 作为本机连接候选，配对返回未加后缀的 GUID。最终版成功匹配并连接一次，`paired_peer_filter=true`、`connection_attempts=1`、`adb_connection_closed=true`；shell UID 辅助进程持续存在。这也直接覆盖了“仅存在自动重命名服务”的修复路径，旧严格匹配会返回 0 候选。开始时记录 `usb=1 wireless=1 charging=1`，联想服务仍被拒绝。
