- 主窗顶部菜单提供切换全屏、替换应用、关闭应用。

- 主次交换保持原任务身份、侧窗持续画面和退出释放沿用既有实测结论；本轮不重复把既有记录声明为新设备通过。

## 边界和持久化

schema 3 → 4 增加 `wallpaperBackground`。版本 1/2/3 的已有渐变和图片保持不变；新配置采用系统壁纸。模型不依赖 Android，`RecentWorkspace` 只处理卡片归属、顺序、身份和焦点。Repository 串行合并和保存，写入成功才启动工作台；失败保留原文件、可重试。

`recentApplications` 是仅限 owner UID 的无参数只读接口，只返回当前用户可启动应用的组件列表，不返回任务 Intent 数据、任意命令或可操作任务 ID。`RecentTaskAccess` 独立封装系统非公开接口；恢复时重新查找任务，不相信客户端历史任务 ID，不接管其他用户或系统分屏容器。没有新增手机 App、root、Shizuku 或任意 shell 执行入口。

`WallpaperBackdrop` 使用公开 `FLAG_SHOW_WALLPAPER` 与窗口模糊 API，不读取/复制桌面壁纸文件，不加入服务主题逻辑。`PickerBackdrop` 临时隐藏承载窗口的合成透明度，恢复原值，TextureView 和 Surface 全程保留。模糊能力由系统和 GPU 决定，省电等状态可能关闭；不能保证全部设备呈现相同的虚化强度。[Android 窗口模糊说明](https://source.android.com/docs/core/display/window-blurs)

## 验证结果

本轮开发与联想实机验证已完成，范围见下表。原始截图、配置快照、任务与窗口记录位于本机 `.runtime/iqoo-parity-20261111/`，不公开无关应用内容。

已通过首轮架构检查、122 项 JVM 单元测试、Debug 构建与 Lint（0 错误）。新增用例覆盖最近应用去重和上限、稳定卡片 ID、分屏归属与焦点、缺失应用保留、保存组合隔离、schema 3 迁移、损坏字段保护、写入失败与重试。

首轮实机问题保留：RootTaskInfo 不能强转 RunningTaskInfo，现改为服务适配层读取必要字段；全屏抽屉的透明窗口曾透出启动页旧帧，现用窗口合成透明度隐藏承载画面并恢复，不销毁 Surface。这些首次失败不能计为验证通过。

收尾又发现联想移除主卡片时，系统自动把释放显示器中的任务提到物理主屏前台，导致工作台停止。现先在原宿主仍可见时迁回自有显示器内的任务、恢复宿主，再释放空显示器；退出整个会话不恢复宿主。重测从抽屉移除主卡片时钟、侧卡片相机和设置均留在工作台，原两张卡片继续运行。自动化工具曾因并发 UIAutomator 注册报错，属于测试工具故障；已改为串行并拒绝读取失败后的旧 XML。
