# 0.14.2 状态栏与背景衔接

2026-11-11，联想 TB323FU / Android 16。本轮新快照为爱奇艺主窗、超级文件第一侧窗、哔哩哔哩第二侧窗，普通横屏、自动旋转 1、user_rotation 1。遵循用户的新顺序，不用上一轮哔哩哔哩主窗的记录恢复。原始证据位于 `.runtime/statusbar-seam-20261111/`。

## 原因与修改

0.14.1 将系统栏设为透明，但背景和壁纸遮罩只画在系统栏之间的 scene 中，状态栏与导航栏透出更亮的壁纸，形成明显横向色带。单独调状态栏为一个固定颜色不能保持壁纸、渐变和图片的连续性。

新增 `InsetBackdropHost`：窗口始终允许背景延伸到系统栏下方，整屏只用一层原背景；普通模式给内部 scene 保留系统栏和开孔的安全边距，全屏收起系统栏后移除边距。没有改变遮罩颜色、模糊半径、卡片布局公式、配置 schema 或服务权限；没有新增截图、模糊计算或帧循环。透明导航栏同时取消分隔线颜色。实现依据为 Android 的透明系统栏与内容安全边距规则：[官方说明](https://developer.android.com/develop/ui/views/layout/edge-to-edge-manually)。

初始化、外观修改及组合切换均应用到同一整屏背景。应用抽屉复用 `InsetBackdropHost`，在自己的整屏深色背景内避让系统栏与搜索键盘；关闭后复用原 Surface。全屏左下角菜单仍避让开孔。

首轮实机确认工作台色带消失，但抽屉仍有相同亮色带（`picker-landscape.png`）；随后将抽屉一起修复。该截图是修复过程记录，不是交付效果。

## 验证

- 普通横屏与竖屏：状态栏、工作台和导航栏背景连续，状态文字可读。主窗及侧栏不覆盖系统栏，原三应用保留。见 `final-normal-landscape.png`、`normal-portrait.png`。
- 在横屏旧状态栏分界处，取 x=600…1399、y=106/107 两行像素，各 RGB 通道平均差从 71.62 降至 0.11（0…255 标度）；只作为这组截图消除横线的辅助证据，不是通用视觉评分。正常 scene 仍为 3040×1764，三张卡片的目标位置、宽度与逻辑画布尺寸和 0.14.1 完全一致。
- 侧栏末尾加号在横屏、竖屏全屏均能打开应用抽屉；抽屉横竖屏背景也延伸至系统栏下方，使用浅色系统图标。见 `final-picker-landscape.png`、`picker-portrait.png`。关闭后原实时画面和全屏状态恢复。
- 整个工作台全屏横竖屏均保留侧栏与左下角菜单；点击菜单返回普通模式后，系统栏背景仍连续。见 `fullscreen-portrait.png`、`fullscreen-landscape.png`。
- 搜索输入检查使用设备当前的浮动输入法，候选栏出现时可继续完成并关闭抽屉；未改输入法设置。本轮未验证固定底部软键盘的完整高度适配。
- 架构脚本、`:app:testDebugUnitTest`（125 项）、`:app:assembleDebug` 与 `:app:lintDebug` 通过，Lint 0 错误、36 警告。未新增模型字段和持久化迁移。

本轮在联想以当前系统壁纸验证；其他厂商、开孔屏、三键导航、自选图片与系统禁用模糊仍需独立实测，不用本次结果推断所有配置通过。
