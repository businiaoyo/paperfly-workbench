# 0.8.0 整个工作台全屏

日期：2026-11-07。versionName 0.8.0 / versionCode 13，调试签名。

## 行为

顶部“全屏”收起工作台操作栏（内存、返回应用、添加、窗口菜单和退出），同时通过当前窗口的沉浸模式收起系统栏。整个工作台覆盖物理屏幕，侧窗仍可见并可交换、滚动和滑动移出。主窗的上边缘为屏幕顶端，右侧与底部尽量占满可用区域；左侧保留侧栏。左下角小“菜单”按钮恢复普通工作台的操作栏。

按新的主窗区域调整全部应用画布的宽高比，避免只放大旧画面造成变形、裁切或大块留白。保持设备的采样比例和密度，主次交换期间不改变画布。全屏、普通模式以及方向变化时保留原有任务和虚拟显示器，应用可以按自己的配置变化策略重排界面。

只操作本 App 窗口的系统栏请求，不改系统全局动画或其他显示设置。参考 [Android 沉浸模式](https://developer.android.com/develop/ui/views/layout/immersive)。荣耀系统自己的多任务提示柄有时仍会浮在最上层；它不占用工作台布局区域。

## 验证

目标机为荣耀 WIN 平板 HES-W00，Android 17 / API 37，MagicOS 11.0.0。横屏场景覆盖 2304×1440、竖屏覆盖 1440×2304；顶部没有工作台菜单占位。主窗顶部为 0，侧栏保持显示。因偶数画布尺寸取整，画面边缘可能有约 1–3 像素差异。

保留用户当时的 6 个应用（爱奇艺 PAD、时钟、抖音、红果免费短剧、哔哩哔哩、哔哩哔哩 HD），临时加入计算器。全屏时点击侧位时钟可交换到主窗，再交换回计算器；旋转后仍保留全屏工作台和原显示器。计算器通过真实按钮完成 `8 + 4 = 12`，不修改应用数据。

全屏下可滚动到后面的窗口；临时计算器通过侧窗手势移出。测试后恢复用户原来的 6 个应用、顺序和主窗，并恢复原自动旋转设置。vivo 参考设备本轮未安装或修改。

最终构建的 `assembleDebug`、`testDebugUnitTest`、`lintDebug` 通过，50 项单元测试、0 失败。新增测试检查全屏主窗的比例、设备采样密度和单应用时的区域边界。现有输入会话、手势、槽位、滚动及动画测试继续通过。

证据位于本机 `.runtime/v08-validation/`，以 `workbench_` 开头的截图是最终“整个工作台全屏”实现；此前探索截图未作为交付证据。`dist/workbench-fullscreen-validation/` 保存最终截图、验证结果、构建日志、源文件 SHA-256 和设备安装包核验。

本轮为限定设备和应用样本的功能验证，未据此证明全部应用、机型、输入法及长时间功耗均兼容。应用自己固定的排版或受保护画面仍受其自身限制。
