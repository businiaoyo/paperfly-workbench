# 0.11.1 右侧返回手势修复

2026-11-08。荣耀 WIN 平板 HES-W00，Android 17 / MagicOS 11，设备 AKDPBB6A08000069。仅更新荣耀，vivo 未安装或修改。

## 问题与实现

旧版在时钟的新建闹钟页面复现：顶部“返回应用”可以返回，物理屏幕右缘滑入没有完成返回。仅处理返回完成回调，不能完整协调承载窗口、应用内触摸和弹窗各自的输入路径。

- `StageBackGesture` 协调系统返回开始、取消与完成；开始时取消原应用触摸，完成时复用现有 `backLiveWindow`，按当前成员转发。
- 系统未接管时，`EdgeBackGesture` 接收屏幕右侧 24 dp 内的滑入；超过 56 dp 并抬手才返回。纵滑先锁定、距离不足、回拖到阈值内、多指和取消不提交。认领后先发 CANCEL，避免滑动同时点击应用或移除侧卡片。
- 坐标从屏幕转换到当前承载窗口，随横竖屏和整个工作台全屏改变。独立识别器不依赖 Android，可直接运行 JVM 测试。
- 工作台的添加面板、窗口菜单、内存及设置弹窗，通过自己的 Window.Callback 复用边缘识别并注册系统返回；先关闭弹窗，不给成员发返回。其他窗口回调完整委托，选择、排序、键盘、菜单和生命周期路径保留。
- 服务、会话校验、显示器所有权、有效 Surface 复用和配置 schema 均未改变。仍为单 APK、免 root、电脑 USB 激活。

## 实机验证

本轮候选和最终包均检查横竖屏及普通/整个工作台全屏；最终包补测三种模式的根页返回、横屏切换成员后返回和弹窗。

| 检查 | 结果 |
| --- | --- |
| 横屏普通模式，物理右缘与右缘内侧补偿区域 | 系统返回、RIGHT_EDGE 两条路径都可返回当前应用 |
| 短滑、纵滑、向内后滑回原位 | 返回请求数不增加，编辑页面保留 |
| 时钟“新建闹钟 → 重复”多级页面 | 一次手势回到编辑页，请求数只增加 1 |
| 横屏全屏、竖屏全屏、竖屏普通模式 | 返回作用于时钟显示器，工作台保持运行 |
| 切换到计算器，再右滑返回 | back_display 是计算器拥有的显示器，侧边时钟保留 |
| 连续两次快速右缘返回 | 两次请求，应用仍有实时画面 |
| 添加应用面板、窗口菜单、内存面板 | 右滑关闭面板；成员返回请求数不增加 |
| 已加入列表选择、上移和完成 | Window.Callback 委托后正常工作 |
| 当前草稿与已保存组合 | 最后逐字段与操作前新快照完全相同，9 个应用及稳定 ID/顺序/样式保留 |
| 旋转设置 | 恢复 accelerometer_rotation=1、user_rotation=1，横屏普通模式 |
