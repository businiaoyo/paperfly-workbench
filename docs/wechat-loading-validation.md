## 微信空白窗口

先快照用户当前配置：当前是微信、红果两个独立卡片，另有三个已保存组合。旧版 0.12 在工作台复现空白背景；微信任务消失，进程日志有 System.exit，桌面正常打开微信可显示。日志中荣耀平行视界的活动分栏仍使用原屏 2304×1440 的坐标，而工作台画布是 1766×1104、276 dpi。

在只针对本工作台微信虚拟显示器的临时尺寸试验中，使用 2304×1440 / 360 dpi 后恢复显示；试验覆盖立即重置。最终通过独立 WindowCanvasPolicy 在创建和调整画布时为荣耀微信保留原屏尺寸、密度和方向，不更改系统平行视界开关，不更改微信数据、不扩大服务权限。其余应用继续使用原画布规则。

最终 APK 实测：微信重新进入、发现页签触摸、主次交换、横竖屏、整个工作台全屏、搜索页键盘显示、第一次返回收起键盘及第二次返回关闭搜索页均能工作。微信的显示器保持复用，主次交换未重建任务。当前配置、顺序、卡片 ID、三个保存组合及旋转设置与测试前一致。测试中的临时保存组合已删除。

本次结论只覆盖当前荣耀平板和当前微信版本（8.0.80）。兼容配置保持原屏比例，自定义窄卡片可能有留白；未逐项验证微信的分屏卡片、视频通话、小程序和其他厂商设备。聊天截图和原始应用日志只留在本地调试目录，交付证据不包含聊天列表。

## 有序加载

恢复时先创建占位卡片，主应用优先启动；等待启动调用返回与首帧两者均完成，再留出 900 ms 缓冲启动下一项。未加载卡片可点按优先打开，触控会推迟尚未开始的启动。启动失败或首帧等待超过 8 秒会继续后续队列，不让一个应用无限阻塞全部应用。加载中暂停内存采样，退出、移除及换组合取消未启动项。

对用户已有 Daily 九应用组合进行恢复测试，实际启动顺序与配置一致，九项均收到首帧，各项之间最短缓冲为 901 ms。本轮从第一个 START 到最后一个 OPENED 约 10.48 秒；这是此次已运行应用样本的恢复记录，不是所有应用的冷启动耗时保证，也不是触控延迟或掉帧测量。加载中 Home 退出后，没有继续启动剩余应用，工作台虚拟显示器被释放。

优先打开实测：计算器先启动，点击尚未加载的第三张“设置”卡片，后续顺序变为设置、时钟，并在设置就绪后自动选为主卡片。首次自动操作在窗口刚建立时点击过早，未构成有效优先请求；等待窗口可接收触摸后重测通过。侧栏末尾加号面板打开、关闭后仍能回到原工作台。

## 激活后返回首页

配对/激活流程记录返回意图。成功时激活页在前台则直接回首页；成功时用户仍在系统设置中则等返回 App 后再回首页。失败留在激活页。主动从已激活的首页打开说明页仍可查看说明，不会立即被弹回。

最终 APK 实测通过：前台无线激活自动回首页；切到系统设置后完成无线激活，设置界面不被打断，返回时回到首页；关闭无线调试导致激活失败时留在激活页；重新开启无线调试重试成功后回首页。复用已配对身份进行真实无线启动，本轮未重新创建配对身份；首次六位配对协议已在 0.12 验证。本次不重复宣称 USB 物理拔线测试通过。
